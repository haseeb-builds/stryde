# Stryde Product Truth

## What Stryde is
Stryde is a persistent situational-intelligence workspace that helps a person understand messy situations, make decisions, move work forward, execute authorized actions, verify what actually happened, and update durable state.

Core loop:

REALITY → SITUATION → UNKNOWN / BOTTLENECK → RECOMMENDATION → AUTHORITY → ACTION → EXECUTION → EVIDENCE → VERIFICATION → STATE UPDATE → NEXT ACTION

## Product principles
- External source material can become an input to a Pursuit without becoming its truth. Stryde preserves the source, extracts its proposed method, maps fit/gaps/conflicts, and adapts it against reality.
- Goals discovered from conversation or sources remain provisional until the user explicitly adopts them; adoption is recorded as a Claim with lineage.
- Stryde absorbs ambiguity instead of turning it into a questionnaire.
- Conversation is working interaction and history, not canonical memory.
- Durable state is evidence-graded and provenance-aware.
- UNKNOWN is valid state.
- Action is not outcome.
- Mechanical success is not real-world verification.
- Models propose; deterministic control authorizes and enforces.
- Human authority remains over consequential decisions.
- Continuity across sessions is a core capability.
- The user should see the current useful move, not a forced questionnaire or giant roadmap.
- Working state is derived and revisable; it is not canonical truth.
- Stryde should eventually perform bounded real work, not remain advice-only.

## V1 boundary
V1 is built as a continuous work loop rather than a situation-analysis endpoint.

The workspace should support:
- attaching public URLs or pasted source material such as videos, courses, roadmaps, articles, and frameworks;
- source interpretation with provenance, method extraction, assumptions, prerequisites, expected outcomes, fit, gaps, conflicts, and goal candidates;
- adaptive pursuit continuity where the source is a candidate strategy, the current Situation is canonical, and real results drive re-planning;
- a genuine HUMAN execution loop: explicit approval → Action → user result → Observation → re-assessment;
- persistent Pursuits and conversation continuity;
- adaptive interpretation of messy input;
- a persisted working-state projection with one current Next Move;
- server-side context assembly so the client cannot define the model's history;
- capability-gated research/source retrieval;
- deterministic Action/Decision/Claim mutations;
- one real controlled execution path;
- evidence capture and deterministic verification.

The user-facing contract is:
REALITY → SITUATION → UNKNOWN/BOTTLENECK → NEXT MOVE → USER/STRYDE WORK → RESULT → EVIDENCE → VERIFICATION → STATE UPDATE → NEXT MOVE.

Broad autonomous web research, arbitrary file extraction, controlled external tools, proactive monitoring, vector memory, multi-agent runtime, organization tenancy, and self-improvement remain later capabilities. The current source path deliberately supports public text URLs and pasted material without pretending unsupported retrieval/execution exists.
